A colorful hands-on repository for exploring the most common retrieval strategies used in Generative AI and RAG pipelines.

This project compares:

- 🔎 Sparse retrieval with BM25
- 🧠 Dense semantic retrieval using embeddings
- ⚡ Hybrid retrieval combining both signals
- 🗂️ Direct vector store similarity search with Chroma

---

## ✨ Why this matters

Retrieval is one of the most important building blocks in Retrieval-Augmented Generation (RAG). The quality of your retriever often shapes the quality of the final answer generated by an LLM.

This repo is a practical playground for understanding how different retrieval methods behave when working with document chunks from PDFs.

---

## 🌈 Repository overview

The examples in this repository:

1. Load a PDF document
2. Split it into chunks
3. Create a searchable index
4. Run a sample query
5. Print the most relevant retrieved chunks

---

## 📁 Project structure

- [Dense_retriever.py](./Dense_retriever.py) — loads a PDF, chunks it, builds a Chroma vector store, and performs dense semantic retrieval.
- [Sparse_retriever.py](./Sparse_retriever.py) — loads a PDF, chunks it, and retrieves relevant text with BM25-based sparse search.
- [Hybrid_retriever.py](./Hybrid_retriever.py) — combines BM25 and dense retrieval to produce a more balanced ranking.
- [VectorStore_retriever.py](./VectorStore_retriever.py) — performs direct similarity search against Chroma without a LangChain retriever wrapper.

---

## 🧩 Retrieval strategies explained

### 1) Dense retrieval
Dense retrieval turns document chunks into embeddings and compares them with the query embedding using vector similarity.

This helps capture semantic meaning rather than just exact keywords.

### 2) Sparse retrieval
Sparse retrieval uses lexical matching. BM25 ranks chunks based on term frequency and document frequency, making it effective when keywords are critical.

### 3) Hybrid retrieval
Hybrid retrieval blends:

- 🔤 keyword matches from sparse retrieval
- 🧠 contextual similarity from dense retrieval

This often gives better results when a query contains both specific terms and broad intent.

## 🛠️ Requirements

Before running the scripts, install the required packages:

```bash
pip install langchain langchain-community langchain-chroma langchain-openai python-dotenv pypdf
```

You will also need:

- Python 3.9+
- An OpenAI API key
- A PDF file to index

---

## 🔐 Environment setup

Create a `.env` file in the project root and add your OpenAI key:

```bash
OPENAI_API_KEY=your_openai_api_key_here
```

The scripts use `load_dotenv()`, so your environment is loaded automatically.

## ▶️ How to run

Run any of the scripts individually:

```bash
python Dense_retriever.py
python Sparse_retriever.py
python Hybrid_retriever.py
python VectorStore_retriever.py
```

Each script follows the same workflow:

1. Load the PDF
2. Split the text into chunks
3. Build the retriever or index
4. Run a sample query
5. Print the top matching chunks

## 💡 Example query

The scripts use a sample query like:

```python
query = "What is the main topic of the document?"
```

You can replace this with your own query to experiment with retrieval quality and ranking behavior.

## ✅ Best practices

- Tune `chunk_size` and `chunk_overlap` based on your dataset.
- Prefer hybrid retrieval when you want a balance of matching and semantics.
- Ensure the PDF path and environment variables are correctly set.
- Persist the vector store if you want to reuse indexed documents across runs.
